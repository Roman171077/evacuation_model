# Evacuation Model

Модель дискретно-шаговой эвакуации людей по связанным участкам (коридор, дверь, лестница и т.д.).

## Структура проекта

- `src/model` — сущности модели (`Person`, `Segment`, `Door`)
- `src/simulation` — логика симуляции и расчётов
- `src/utils` — общие константы (группы мобильности, коэффициенты типов участков)
- `scenarios` — готовые сценарии запуска
- `main.py` — точка входа

## Как работает код

### 1) Входные данные сценария

Сценарий (см. `scenarios/test_case_1.py`) собирает:

- `sections`: граф участков эвакуации (`Segment`/`Door`) с геометрией и связями (`next_section_id`)
- `people`: список людей (`Person`) с группой мобильности, стартовым участком и позицией `x`
- `params`: параметры симуляции (`SimulationParams`) — шаг времени `dt`, лимит времени, режим зимней одежды

### 2) Базовые сущности

- `Person` хранит состояние человека: позицию, текущую скорость, флаг завершения эвакуации и время выхода.
- `Segment` описывает участок пути: длину, ширину, ширину выхода, следующий участок и вместимость «ряда» у выхода.
- `Door` — специализированный `Segment`, который принудительно имеет тип `door`.

### 3) Расчёт скорости

Для каждого человека скорость пересчитывается на каждом шаге:

1. Берётся базовая скорость группы мобильности из `MOBILITY_GROUPS`.
2. Умножается на коэффициент типа участка (`SECTION_TYPE_SPEED_FACTOR`).
3. Корректируется коэффициентом снижения от локальной плотности (`density_reduction_factor`).
4. Ограничивается снизу (`>= 0.01 м/с`), чтобы модель не «замирала» полностью.

### 4) Локальная плотность и «ряды»

Люди внутри участка сортируются по координате `x`.

- Близко стоящие люди объединяются в группу-«ряд» (`build_row_groups`) с шагом `ROW_STEP_X`.
- Для каждого ряда считается локальная плотность (`compute_local_density`).
- Все люди ряда получают скорость из этой локальной плотности.

Это имитирует, что в плотной группе люди замедляются сильнее.

### 5) Два прохода внутри шага симуляции

Метод `EvacuationModel.step()` делает два прохода:

1. **Кинематика:** считает черновую позицию `x_raw = x - v * dt`.
2. **Переходы между участками:**
   - если `x_raw >= 0`, человек остаётся на участке;
   - если `x_raw < 0`, человек пытается пройти через выход участка.

Если у участка нет `next_section_id`, человек считается эвакуированным (`finished=True`, фиксируется `exit_time`).

Если следующий участок есть, применяется ограничение пропускной способности.

### 6) Пропускная способность выхода

Функция `compute_capacity_people_per_step` считает, сколько людей можно пропустить за текущий шаг:

- оценивает среднюю плотность на участке;
- считает интенсивность потока `q` (м/мин) через среднюю скорость и плотность;
- переводит поток в «людей за шаг» с учётом `exit_width`, `dt` и средней площади человека;
- использует `transfer_credit` (накопление дробной части), чтобы корректно моделировать целочисленный пропуск.

Если желающих пройти больше, чем разрешено:

- часть проходит в следующий участок;
- остальные выстраиваются в очередь у выхода по `row_capacity`.

### 7) Приоритет очереди

Параметр `queue_priority_most_negative_first` задаёт сортировку кандидатов на проход:

- `True` — первыми проходят те, кто «сильнее вышел за границу» (`x_raw` более отрицательный);
- `False` — приоритет по `pid`.

### 8) Цикл симуляции

`run()` повторяет шаги, пока:

- не эвакуированы все люди,
- и не достигнут `max_time`.

На выходе возвращает:

- общее время эвакуации,
- количество эвакуированных,
- общее число людей.

## Запуск

